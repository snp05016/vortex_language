# Reading list

<p class="page-intro">Every source this guide cites, with a note on what each one is good for and which stages it helps with. All links were checked in September 2026.</p>

You do not need to read all of this. If you read only two things alongside the
guide, make them the LLVM Kaleidoscope tutorial and the first half of
*Crafting Interpreters*. Everything else is for when a particular stage gives
you trouble.

## Start with these two

**LLVM, "My First Language Frontend with LLVM Tutorial".** The tutorial builds
a small language called Kaleidoscope, in C++, over ten chapters. It says it
"assumes you know C++, but no previous compiler experience is necessary".[^kal]
It also says plainly that it skips software engineering best practice to keep
the code short, so read it for the ideas rather than for code
organization.[^kal]

| 2 | [Implementing a Parser and AST](https://llvm.org/docs/tutorial/MyFirstLanguageFrontend/LangImpl02.html) | [3. The parser](stage-3-parser-and-tree.md) |

| 5 | [Extending the Language: Control Flow](https://llvm.org/docs/tutorial/MyFirstLanguageFrontend/LangImpl05.html) | [7. Functions and control flow](stage-7-functions-and-control-flow.md) |

**Robert Nystrom, *Crafting Interpreters*.** The book builds two
implementations of one small language, Lox. The first, jlox, is written in Java
and runs the syntax tree directly. The second, clox, is written in C and
translates the program to bytecode before running it.[^ci-intro] Neither
produces machine code, but the front-end chapters carry over to Vortex almost
unchanged, and the prose is the clearest in this list.

## Building in small steps

**Abdulaziz Ghuloum, "An Incremental Approach to Compiler Construction".** A
short workshop paper, and the source of the idea that a compiler can grow in
steps where each step is a complete, working compiler for a slightly larger
language.[^ghuloum] It compiles a subset of Scheme to x86 assembly and comes
with an automated test suite. Read it before [stage 0](stage-0-workbench.md);
it takes an afternoon.

**Nora Sandler, "Writing a C Compiler" (blog series and book).** The blog
series starts from a program that only returns the number 2, and names
Ghuloum's paper as its model.[^sandler-blog] The later book grows the same idea
into a compiler for a large subset of C that produces x64 assembly. Its
algorithms are given "in pseudocode", so it does not tie you to any
programming language.[^sandler-book] It is the closest thing in this list to a
full, modern, step-by-step course.

## Parsing

**Vaughan Pratt, "Top Down Operator Precedence".** The 1973 paper behind a
parsing technique that handles operator precedence neatly.[^pratt] The paper
itself is dense.

**Aleksey Kladov, "Simple but Powerful Pratt Parsing".** A modern, readable
explanation of Pratt's technique.[^matklad-pratt] Read this instead of the
paper unless you are curious about the history.

**Aleksey Kladov, "Resilient LL Parsing Tutorial".** About parsers that keep
going after an error and recover "as much syntactic structure from erroneous
code as possible".[^matklad-resilient] Useful when you work on error recovery
in [stage 3](stage-3-parser-and-tree.md).

**Dick Grune and Ceriel Jacobs, *Parsing Techniques: A Practical Guide*.** A
large reference book on parsing methods of every kind.[^grune] Look things up
in it; do not read it front to back.

## Error messages

**Clang, "Expressive Diagnostics".** A short page showing, with before and
after examples, what makes a compiler error readable: exact columns, a caret
under the problem, highlighted ranges, and suggested fixes.[^clang-diag]

**Evan Czaplicki, "Compiler Errors for Humans".** A blog post about the Elm
compiler's error messages and the thinking behind them.[^elm]

**Rust Compiler Development Guide, "Errors and lints".** How a large
production compiler organizes its diagnostics.[^rustc-diag]

All three belong with [stage 1](stage-1-source-and-diagnostics.md).

## The middle and the back end

**LLVM Language Reference Manual.** The full definition of LLVM's intermediate
representation.[^langref] It is a reference, not a tutorial. If Vortex uses
LLVM, you will look things up here often. The practical setup pages,
[Getting Started](https://llvm.org/docs/GettingStarted.html)[^llvm-start] and
[Writing an LLVM Pass](https://llvm.org/docs/WritingAnLLVMNewPMPass.html),[^llvm-pass]
come later.

**Michael Rodler and Mikael Egevig, *Mapping High Level Constructs to LLVM
IR*.** Explains "how LLVM based compilers map high-level language constructs"
into LLVM IR, with sections on basic constructs, control flow, and
interoperating with a runtime library.[^mapping] It is the most direct help for
stages [6](stage-6-first-machine-code.md) to
[8](stage-8-data-in-memory.md).

**Cytron and others, 1991; Braun and others, 2013.** The two standard papers
on static single assignment form, a way of writing a program in which every
variable is assigned exactly once. The first is the classic
construction;[^cytron] the second is a simpler one that works directly from a
syntax tree.[^braun] You only need these if you build your own IR. LLVM builds
this form for you.

**Sarkar, Waddell and Dybvig, 2004; Keep and Dybvig, 2013.** Two papers on the
nanopass approach, which builds a compiler from many very small passes, each
doing one job.[^nanopass][^nanopass-2013] Worth reading as a design idea even
if you never use the framework.

## Testing

**LLVM, lit and FileCheck.** The tools LLVM itself uses for its test
suite.[^lit][^filecheck] lit finds and runs test files; FileCheck checks that
a program's output contains the expected lines. They are one example of how
to organize tests for [stage 0](stage-0-workbench.md) and
[stage 11](stage-11-release.md). Vortex is free to choose something simpler.

## Numbers

**David Goldberg, "What Every Computer Scientist Should Know About
Floating-Point Arithmetic".** The standard explanation of why decimal
arithmetic on a computer is not exact.[^goldberg] Long and mathematical in
places, but the first sections are enough for
[stage 9](stage-9-runtime-safety.md) and
[stage 10](stage-10-matrix-multiplication.md).

## Textbooks

These four books are worth having nearby but are not required for any stage.

- Aho, Lam, Sethi and Ullman, *Compilers: Principles, Techniques, and Tools*,
  2nd edition, 2006. The long-standing standard textbook, often called the
  dragon book.[^dragon]
- Cooper and Torczon, *Engineering a Compiler*, 3rd edition, 2022.[^eac]
- Appel, *Modern Compiler Implementation in ML*, 1998.[^appel] Also published
  in C and Java editions.
- Wirth, *Compiler Construction*. A short book that builds one complete
  compiler, for a small language called Oberon-0, targeting a simple RISC
  processor. The author has made the revised edition free to
  download.[^wirth]

## After v0.1

**MLIR, "Toy Tutorial".** Toy is described as "a tensor-based language" that
can "perform some math computation".[^toy] That makes it the nearest neighbour
to where Vortex wants to go after v0.1, with tensors and GPUs. Leave it until
then.

**Rust Compiler Development Guide, "Overview of the compiler".** A tour of a
large production compiler. It is a useful contrast: rustc says it "is not
organized as a series of passes", while the Vortex compiler
is.[^rustc-overview] Seeing why a very large compiler made a different choice
helps you understand the simpler one.
